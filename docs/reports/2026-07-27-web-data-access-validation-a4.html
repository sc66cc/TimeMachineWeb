TimeMachine 地学数据 Web 接入与性能验证阶段报告

2026-07-27
盆地 · 板块 · PBDB · 图集 · Raster
核心判断：Web/Cesium + Martin 已从概念验证推进到可组合的数据底座， 适合作为在线浏览、检索、分享和轻量分析主入口；Unity 不宜立即整体替换，应保留为 高端渲染、离线分析和专业工作站。建议形成“双前端、一数据底座”。

一、已验证成果

对象关键结果阶段结论
盆地/板块地图 PostGIS → Martin MVT → MapLibre 链路打通；完成跨 180° 经线异常识别与接缝策略验证。 可按视口发布矢量瓦片，避免全量 GeoJSON。
球面板块重建 503 个多边形、649,905 个三角面、241 个 Plate ID；0–1100 Ma；pyGPlates 黄金坐标误差达小数点后 8–9 位。 刚性有限旋转、重建树、四元数与拾取链路正确。
PBDB 大规模点 275,347 行接受 275,291 行；186 个 Plate ID；WGP1 覆盖 10k–5M 点，5M 约 95.4 MiB，单 buffer / 单 draw call。 CPU 时间更新由点数 N 降为活动板块数 P。
时间图集 90 个真实帧生成 JPEG 95、z0–z4 MBTiles（约 302 MiB）；151 个 5 Ma 节点；4,314 次瓦片请求通过。 支持按需加载、最近真实帧解析和邻帧预热。
标量 Raster+CPT 9 个栅格、8 组色带生成 PNG MBTiles（约 66 MiB）；NoData 透明；346 次请求通过，34 个 HTTP 204 符合预期。 NetCDF/GeoTIFF、色带和透明区可统一进入数字地球。
工程质量 13 个测试文件、57 项测试通过；TypeScript 与 Vite production build 通过。 已形成可持续回归的 Web runtime。
性能口径：自动化浏览器使用 SwiftShader，只证明 5M 点、Raster 和图集链路可加载、可交互、无 WebGL 错误；不能替代目标显卡上的 FPS、P95 帧时和显存验收。

二、与当前 Unity 方案对比

维度Web/Cesium + Martin当前 Unity 方案
访问发布 零安装、URL 即开即用；易接入 Nginx、CDN、权限与业务页面。 需安装、打包和升级；但离线运行与环境可控性更强。
大数据链路 MVT/MBTiles/manifest 按视口和时间加载，适合在线数据服务。 现有全量 RPC、整幅 GZIP PNG、完整 LayerList 保存方式在大数据下压力较高。
渲染性能 Worker + GPU buffer + shader；跨平台，但受 WebGL、浏览器内存和 GPU 配额约束。 原生 GPU、Compute Shader、内存控制和性能分析更强，适合极限规模和高保真效果。
产品迭代 Vue/TypeScript 易整合搜索、目录、协作和云项目，部署迭代快。 3D 交互成熟，但业务 UI、Web 分享和多端交付成本较高。
科学场景 已验证刚性板块重建，适合标准化在线复现。 更适合复杂桌面工作流、离线计算和高阶可视化；两端均需补充变形网络。

三、建议与下一步

  1. 双前端：Web 做默认在线入口，Unity 做专业工作站；统一引用 DatasetVersion、PlateModelVersion 与 RasterTileSet。
  2. 生产化：固化 PostGIS + 只读 Martin + Nginx/HTTPS + 对象存储/CDN；导入改为异步 Job 和不可变 manifest。
  3. 同机 A/B：用相同数据、相机和硬件测试 275k/1M/5M 点与 90 帧图集，统一记录首屏、FPS、P95、CPU/GPU 内存和交互延迟。
  4. 科学正确性：持续用 pyGPlates 校验多 Plate ID、多年代、反经线与球面接缝；复杂变形和连续时间 Raster 先服务端派生。
